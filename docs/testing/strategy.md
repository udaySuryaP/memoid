# Test strategy

Unit and contract tests cover typed configuration, redirect safety, log redaction, package boundaries, MCP v2 compatibility, and the exact screen manifest. PostgreSQL integration tests prove migration behavior, transaction-local RLS isolation under pool reuse, and one synthetic pg-boss job. Playwright covers Chromium desktop/mobile, keyboard behavior, axe checks, and committed screenshot baselines.

Stage 10A adds pure-domain tests for UUIDv7, policy/default/version, Context Identity, assertion origin/confirmation, Source frontier ordering, and Candidate gap safety. Isolated real-PostgreSQL-18 databases prove blank-to-latest migration, repeated migration, down/up round trip, UUID generation, schema constraints, composite Project scoping, policy-version concurrency, origin/confirmation integrity, per-Source/ref frontier ordering/monotonicity, Context Identity/current-record concurrency, cumulative provenance/coverage, and deny-by-default product-schema permissions. The Candidate proof explicitly completes N+1 before N and verifies that the reconciled watermark stays behind the gap.

API contract tests prove that `/health` remains liveness-only when PostgreSQL fails and that `/ready` returns sanitized ready/not-ready responses. Integration tests exercise the real bounded PostgreSQL `SELECT 1` probe against both available and unavailable endpoints. A repository contract assertion preserves the V1 prohibition on ordinary external MCP/API clients triggering Source refresh/synchronization.

The repository-native Stage 9C/9D implementation contract is split deliberately: `docs/implementation/stage9d-implementation-contract.json` preserves the durable synchronized Stage 9C baseline, four-plane/checkpoint/review/frontier/engine/GitHub/gate invariants and the rule that repository guidance does not independently authorize workstreams; `docs/implementation/stage9c-failure-race-contract.json` is the single complete machine-readable source for all 83 Stage 9C failure/race scenarios.

Contract tests require exactly 83 unique sequential scenario IDs and non-empty scenario, detection, canonical behavior, user-visible behavior, recovery (or explicit `NOT_APPLICABLE`), idempotency/concurrency (or explicit `NOT_APPLICABLE`), audit expectation, valid Stage 10/HQ owners, proof/test expectation, and proof-gated mechanism status. Exact semantic assertions preserve the controlling checkpoint-confirmation boundary, AI-inference automatic-denial rule, contiguous Candidate frontier, 105→106 lost-wakeup rule, provider-outage continuity, policy/frontier final recheck, Manual→Automatic backlog behavior, branch authority, Source-refresh denial, Working/Reviewed/Source precedence, grant revocation, delete/archive fencing, and degraded Resume behavior.

These tests validate implementation semantics and ownership without choosing product tables, enum/type names, cursor representation, lease/lock primitives, MCP schemas, provider SDKs, or UI routes. Later vertical tests must turn the fixture scenarios into runtime proof at their named gates; editing prose alone must not weaken or bypass the machine-readable contract.

Repository-governance tests intentionally avoid volatile `Stage X ACTIVE/BLOCKED` assertions. They prove instead that the synchronized implementation-contract baseline is HQ-reconciled Stage 9C, repository files do not independently authorize a current workstream, current authorization is checked against canonical HQ/project state, branch → CI/security → PR → HQ review → merge remains mandatory, direct pushes to `main` remain prohibited, Stage 2 negative evidence remains visible, and the Stage 10 entry map defines gates rather than live authorization.

`pnpm test:security` isolates the existing redirect/return-intent and log-redaction foundation security tests. `pnpm sast` is a separate, fail-closed JavaScript/TypeScript static-security pass. The Security workflow also runs Secretlint, dependency audit, and gitleaks; dependency review remains capability-gated as documented in `docs/governance/repository.md`.

Windows and Linux keep explicit platform-specific golden images so operating-system font rasterization cannot mask product regressions. New platforms establish baselines intentionally; later changes fail at a strict 1% pixel-difference threshold. CI artifacts retain reports and diffs.
